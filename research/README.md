# Исследование: можно ли сделать бота из макро + ICT

Два бэктеста без подгонки: все пороги взяты из терминала (TOPDOWN, правила индикатора ICT-QPS v21) и не оптимизировались.
Запуск: `node research/step1_regime.js`, затем `node research/step2_entries.js`. Подробные цифры — в `results/*.json`.

## Шаг 1. Макро-режим на дневках (2008 → октябрь 2026)

Nasdaq-100 и S&P 500, 10 макро-факторов TOPDOWN (ликвидность ФРС, 10Y, доллар, VIX, 2Y против ставки, реальная
доходность, тренд инфляции, кредитный спред BAA−10Y, структура VIX, NFCI). Каждый ряд — с задержкой публикации.
Правила взяты из 2008–2016, проверка — 2017–2026 (новые для правил данные). Издержки 2 б.п. на сделку.

| Nasdaq-100, 2017–2026 (проверка) | Доходность в год | Sharpe | Макс. просадка | В рынке |
|---|---|---|---|---|
| Купить и держать | 20.8% | 0.94 | −35.6% | 100% |
| Тренд (цена > SMA50) | 13.0% | 0.91 | −19.4% | 72% |
| Тренд + макро-фильтр (счёт ≥ 0) | 13.6% | **1.06** | −18.9% | 60% |
| Тренд + размер по макро | 11.7% | 1.04 | −18.7% | 66% |

S&P 500 за 2017–2026: «тренд + размер по макро» — Sharpe 0.98 против 0.78 у «купить и держать», просадка −9.3% против −33.9%.

**Вывод.** Макро-счёт **не предсказывает направление**: доходность следующих 20 дней при счёте ≥ +3 и ≤ −3 почти
одинаковая, ни один фактор по отдельности не значим (|t| < 1.4). Но как **фильтр риска** он работает: срезает просадки
и волатильность, улучшает доходность на единицу риска, хотя общая доходность ниже, чем у «купить и держать».
Применение — размер позиции и защита счёта (важно для трейлинг-просадки проп-фирмы), а не сигнал входа.

## Шаг 2. ICT-входы как реальные сделки (перпы QQQ/SPY = NQ/ES, апрель → октябрь 2026, часы CME)

Каждое первое касание RB / OB / FVG (15m) и каждый вход «свип + реклейм» по открытиям 00:00 / 09:30 / 10:00 NY:
вход на уровне, стоп за тенью / дальней границей, цель 2R (1R и 3R для устойчивости), выход по времени через 4 часа.
~3000 сделок на каждом инструменте.

| NQ, издержки CME | Сделок | Средний результат | t |
|---|---|---|---|
| RB / OB / FVG — все | 2478 | −0.18…−0.29R | значимо < 0 |
| FVG по тренду в киллзону | 287 | −0.03R | ≈ 0 |
| FVG против тренда | 330 | −0.50R | значимо < 0 |
| **Открытие 00:00 — все** | 245 | **+0.13R** | 1.4 |
| **Открытие 00:00 по тренду в киллзону** | 43 | **+0.33R** | 1.5 |

ES: открытие 10:00 по тренду — +0.30R (n=41, t=1.4); открытие 00:00 по тренду в киллзону — +0.30R (n=42, t=1.3).

**Выводы.**
1. Зоны RB / OB / FVG как механический вход **убыточны** после издержек, даже с фильтрами тренда, киллзон и макро.
   То, что зона «дала реакцию» (метрика ICT-панели), не значит, что сделка с таким стопом прибыльна: реакция не учитывает,
   что цена до неё успевает выбить узкий стоп.
2. Вход против тренда — худшее, что можно делать (FVG против тренда −0.5R на сделку).
3. На перпах Binance (комиссия ~0.07% за круг) всё уходит в −1R: стопы у этих уровней слишком узкие для таких издержек.
   Торговать это можно только фьючерсами CME (NQ/MNQ), где издержки в ~20 раз меньше.
4. **Кандидаты:** вход «свип + реклейм» от открытия 00:00 NY по тренду (NQ, обе половины периода в плюсе) и от 10:00 по
   тренду (ES). Но t ≈ 1.3–1.5 при ~40 вариантах проверки — это ещё не доказательство, такой результат может быть
   случайностью. Нужна проверка вперёд (paper trading) на 60–100 сигналов.
5. Макро-фильтр внутри дня не помог.

## Что из этого следует для бота

- Полностью автоматический бот на зонах ICT — **нет**: отрицательное ожидание после издержек.
- Реалистичная схема: **макро → размер позиции**, **тренд → разрешённое направление**, **вход только по кандидатам
  (открытия 00:00 / 10:00 с реклеймом)**, **запреты** вокруг CPI / NFP / FOMC и отчётов гигантов.
- Следующий шаг — сигнальный бот без исполнения: терминал присылает сигнал (вход, стоп, цель, контракты MNQ/NQ),
  ведёт журнал и считает результат вперёд. Через 2–3 месяца — решение по реальным цифрам. Для Apex это полуавтомат
  (вход делает человек), что соответствует их правилам.

Ограничения: 6 месяцев внутридневной истории (бесплатные данные), объём для фильтров — с перпа Binance, проскальзывание
моделируется грубо (~1 пункт NQ на круг), в одной свече «стоп и цель» считается стопом.

## Шаг 3. RB и открытие 10:00 подробно (12 инструментов, апрель → октябрь 2026)

`node research/step3_rb_10am.js`. Индексы (QQQ/SPY = NQ/ES) с издержками CME; акции и ETF (IWM, SMH, NVDA, AAPL, MSFT,
META, AMZN, GOOGL, TSLA, AVGO) с издержками 2 б.п. и только в часы биржи США. Цель 2R (3R в скобках), стоп за тенью.

**Rejection block — решает точка входа.**

| RB, вход | Индексы NQ/ES | Акции и ETF |
|---|---|---|
| край зоны (шаг 2) | −0.27R (n 1774) | −0.16R (n 1822) |
| **середина зоны (CE, как в индикаторе)** | **+0.11R** (n 953, t 2.3) | **+0.18R** (n 1200, t 4.2) |
| CE по тренду | **+0.20R** (t 2.4; 3R: +0.30) | **+0.24R** (t 3.1; 3R: +0.31) |
| CE по тренду + киллзона | +0.21R (t 1.6) | +0.28R (t 3.0; 3R: +0.40) |
| вход с подтверждением (закрытие из зоны) | ≈ 0 | ≈ 0 |

CE по тренду в плюсе на 11 инструментах из 12 (кроме AAPL), обе половины периода в плюсе. Это самый устойчивый результат
всего исследования. Почему: стоп от середины зоны вдвое короче, а цена часто прокалывает край зоны прежде чем развернуться.
Фильтры индикатора «RB в макро-окне» и «RB со снятием ликвидности» лучше не делают.

**Открытие 10:00 NY (свип + реклейм).**

| 10:00, только реклейм с 10:00 до 12:00 | Индексы NQ/ES | Акции и ETF |
|---|---|---|
| стоп индикатора (0.5 ATR) | **+0.73R** (n 49, t 3.4, win 59%) | −0.10R |
| стоп за экстремумом свипа | **+0.68R** (n 46, t 3.3) | −0.16R |
| по тренду, стоп индикатора | +0.90R (n 26, t 3.2) | −0.05R |
| любое время дня | +0.08R (n 216) | −0.08R |

Работает только на индексах и только в утреннюю сессию (10:00–12:00). Выборка маленькая (около 50 сделок, QQQ и SPY часто в
одни дни), а вариантов проверено много — это сильный кандидат, но не доказанное преимущество.
Открытие 00:00 по тренду на индексах: +0.24R (t 2.1); на акциях — в минусе.

**Итог для бота:** 1) RB с входом от середины зоны по тренду (NQ/ES); 2) реклейм открытия 10:00 в 10:00–12:00 на NQ/ES.
Оба — в сигнального бота с журналом для проверки вперёд. Вход «край зоны» и вход с подтверждением — не использовать.

### Шаг 3b. Вход сразу при касании RB (от края зоны) — можно ли его спасти

`node research/step3b_rb_edge.js`. Лимит на краю тела, проверены 9 способов управления сделкой × 3 фильтра × 2 группы.

| Вход от края RB, цель 2R если не указано | NQ/ES все | NQ/ES по тренду | Акции все | Акции по тренду |
|---|---|---|---|---|
| стоп за тенью, цель 1R | −0.34R (win 36%) | −0.34R | −0.22R | −0.23R |
| стоп за тенью, цель 2R | −0.27R | −0.29R | −0.16R | −0.14R |
| стоп за тенью, цель 3R | −0.23R | −0.22R | −0.12R | −0.07R |
| стоп шире на 0.5 ATR | −0.20R | −0.16R | −0.10R | −0.12R |
| безубыток после +1R | −0.27R | −0.27R | −0.16R | −0.16R |
| половина на краю + половина в CE | −0.25R | −0.25R | −0.14R | −0.13R |
| *для сравнения: только CE* | *+0.11R* | *+0.20R* | *+0.16R* | *+0.21R* |

Все 54 комбинации в минусе. При цели 1R выигрывает лишь 36% сделок на NQ/ES — хуже монетки: после касания края цена
**обычно идёт глубже в зону** (до середины доходит в ~55% случаев), и только оттуда разворачивается. Край RB — не точка
входа, а сигнал «приготовиться»: ордер ставится на середину зоны, стоп за тенью.

### Шаг 3c. Вход на возврате: цена зашла в RB, ордер на начале зоны, срабатывает при выходе обратно

`node research/step3c_rb_return.js`. Ордер стоит на краю тела, пока 5m-свеча закрывается внутри зоны (до 2 ч после касания);
исполняется, когда цена выходит из зоны в сторону сетапа (свеча с гэпом за край — по цене открытия).

| Вход на возврате, цель 2R (3R) | NQ/ES | Акции и ETF |
|---|---|---|
| стоп за тенью RB — все | −0.01R (3R: 0.00), n 865 | −0.13R (t −3.0) |
| стоп за тенью RB — по тренду + киллзона | +0.10R (3R: +0.28, t 1.6), n 112 | −0.17R |
| стоп за самой глубокой точкой захода | −0.28R (t −6.1) | −0.38R |
| только если цена дошла до CE | ≈ 0 | −0.26R |

Лучше входа от края (−0.27R), но хуже лимита в середине зоны (+0.11 / +0.20R по тренду): ожидание выхода из зоны
стоит цене входа примерно половину зоны, а стоп остаётся тем же. Короткий стоп за глубиной захода выбивается ретестом.
Единственный плюс (по тренду в киллзону на NQ/ES, цель 3R) — 112 сделок и t 1.6, то есть статистически не отличим от нуля.


## Шаг 4. «Rejection Blocks + Fibonacci confluence» (стратегия из ТЗ), январь → октябрь 2026

`node research/step4_rbfib.js`. Правила — ровно как в терминале (`src/rbfib.js`), заданы заранее:
RB на 5m — тень ≥ 50% свечи и ≥ 0.5 ATR, закрытие в ту же сторону; контекст — свип пула ликвидности (EQH/EQL, свинги,
хаи/лои сессий, дня, недели) на этой или двух прошлых свечах, или тень в OB/FVG 15m той же стороны, или через открытие
00:00/10:00 NY; фибо от тени RB до экстремума импульса (перетягивается на каждом новом экстремуме), импульс ≥ 2 ATR;
лимит на открытие RB существует, только пока оно в зоне 0.62–0.79; стоп за тенью + 0.1 ATR; цель 5R; выход до 16:55 NY;
не больше 3 сделок в день, после 2 убытков подряд — стоп до конца дня; одна позиция на инструмент.

| Цель 5R, средний R на сделку | NQ/ES | Акции и ETF |
|---|---|---|
| без фибы (лимит сразу на открытие RB), все | −0.20R (n 1169, t −3.4) | −0.32R (t −7.4) |
| с фибой OTE, все | −0.13R (n 296) | −0.21R |
| с фибой, по тренду | −0.01R (n 141) | −0.17R |
| **бот по ТЗ** (тренд + ≤3 в день + стоп после 2 убытков) | **+0.01R** (n 130, t 0.1, win 19%) | **−0.15R** (n 208) |
| то же, вход в середину RB (CE) вместо открытия | +0.12R (n 57, t 0.4) | −0.29R |
| цель 3R / 2R вместо 5R | +0.03R / 0.00R | −0.10R / −0.21R |
| цель «ближайший пул ликвидности» | −0.60R | −0.23R |

По контексту (NQ/ES, по тренду): OB/FVG 15m +0.10R (n 84), свип ликвидности +0.12R (n 15), открытие 00:00/10:00 −0.28R.
По инструментам бот по ТЗ в плюсе на 3 из 12 (QQQ +0.05, MSFT +0.17, TSLA +0.30).

**Вывод.** Фибо OTE реально помогает — отсекает худшие входы (−0.20R → −0.13R, по тренду −0.11R → −0.01R), и правила
риска срезают просадку, но преимущества у стратегии нет: на NQ/ES около нуля, на акциях в минусе. Цель «до пула
ликвидности» — худший вариант: у пулов цена чаще разворачивается раньше. В терминале стратегия работает как третий сетап
бумажного бота («RB + фибо») — для проверки вперёд, не для реальных денег.
